# Godot-dotnet-training
A Godot C# training program for learning the engine and design practices.

## Instructions
- This is an open ended project designed to familarize yourself with the Godot engine and practices, while also evaluating your technical skills. Treat this as an interview test.

1. Fork this repository in Github.
2. Clone the repository and open the project in the Godot C# editor.
3. Implement a short (roughly two-week) project of your creative choice, meeting all of the requirements listed below.

## Requirements

### Issue Workflow
- You must use a Github Issue-driven workflow. 
- For each feature you intend to implement, first create an Issue card on Github (Issues must be enabled) and detail a description of the problem you're trying to solve in markdown format.
- After the Issue card is created, create and checkout a new branch through git.
- Make modular commits in your locally checked out branch as you work.
- Once ready for review, open a PR in Github (I like to do this immediately after branch creation) to merge your branch into main. In the description of your PR, explicitly say "Closes #{issue-id}" to reference your Issue card and have it be automatically closed when the PR is merged.

### Design Patterns

Your program must make use of the following design patterns at least once:
1. State Machine (FSM)
2. Global Signal Bus
3. *Def / *Data / *DataFactory Resources

### Assets

Make use of the provided assets pack in `assets/`.

### GUI

Menus are not required but you may find an in-game HUD to be beneficial.

### Objectve

Define a clear game objective with quantifiable progress and discrete game states.

### Agentic Engineering

Agentic Engineering or AI coding is permitted and encouraged, but not required. If you do make use of these tools, you must implement a AGENTS.md file. We recommend using Cursor for an Agentic IDE.

### Deliverable

You must export your finished product in a Linux supported format by the due date (Friday, 2026/08/21).
